# Polish pass 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every `/play` screen fit one desktop viewport, tidy the results bar, add a profile menu (rename, avatar, sign out) with a new neon avatar set, tag demo players on the leaderboard, add a camera zoom slider, and credit the yoga pose dataset.

**Architecture:** New logic goes in new, small modules (`src/ui/avatars/`, `src/ui/profile/`, `src/ui/camera/`) with pure functions under unit tests. Screens and `index.css` get the smallest edits that wire those in. The camera zoom is applied as one rectangle (`frameRect`) given to a wrapper that holds both the `<video>` and the overlay `<canvas>`, so everything drawn on the canvas stays locked to the picture at any zoom without touching overlay or scoring code.

**Tech Stack:** React 19, TypeScript, Vite, Vitest, Supabase JS, Playwright (smoke and screenshots).

**Spec:** the "Rehabeat polish pass 2" request (items 1 to 8), quoted in the PR description.

## Global Constraints

- Don't change scoring maths, tolerances, timing or audio logic (`src/scoring/`, `src/audio/`, `src/pose/` stay untouched, and so do the camera constraints).
- Desktop is `min-width: 1024px`: every `/play` screen fits `100dvh` with no vertical or horizontal scroll, on the page or inside any element. Content max width 1200px, centred. Below 1024px it may stack and scroll. `/` stays scrollable.
- Display name: trimmed, 1 to 20 characters, saved to `profiles.display_name`.
- 12 to 16 avatars, inline SVG written here, background `--color-void` (#05060c), drawn in gold, cyan, white (pink only as a small accent).
- Zoom: slider only, no automatic zoom. Default is the middle value, saved in `localStorage`.
- Every task ends with `npm test` green; the branch ends with `npm test`, `npm run smoke` and `npm run build` green.

## Review Focus

- The migration not applied yet on the live Supabase: loading the profile and the leaderboard must fall back to the old columns rather than fail. Test: `toLeaderboardRow` maps a row without `is_sample` / `avatar_id` to `isSample: false, avatarId: null`.
- A stored zoom that is junk (`"abc"`, `"7"`, storage blocked): `loadZoom` returns `DEFAULT_ZOOM` or the clamped value, never NaN. Test in `zoom.test.ts`.
- A camera frame with the same aspect as the stage: cover and contain are equal, and the slider must be a no-op without dividing by zero. Test: `frameRect` with equal aspects gives the same rect at 0, 0.5 and 1.
- A display name of only spaces, or 20 emoji: refused for being empty; emoji are counted as code points like Postgres `char_length`. Tests in `displayName.test.ts`.
- Esc pressed inside the open profile menu: it closes the menu and does not also send the player back to the song menu. Covered in the screenshot walk (menu closes, screen unchanged).

### Task 5: Camera zoom

**Files:**
- Create: `src/ui/camera/zoom.ts`, `src/ui/camera/zoom.test.ts`, `src/ui/camera/framing.ts`, `src/ui/camera/framing.test.ts`, `src/ui/camera/zoomStore.ts`, `src/ui/camera/ZoomControl.tsx`
- Modify: `src/ui/Stage.tsx`, `src/ui/CalibrateScreen.tsx` (renders `<ZoomControl session={session} />`), `src/index.css` (stage)

**Interfaces:**
- `interface Size { width: number; height: number }`, `interface FrameRect { x: number; y: number; width: number; height: number }`.
- `DEFAULT_ZOOM = 0.5`, `ZOOM_KEY = 'rehabeat.cameraZoom'`.
- `frameRect(stage: Size, video: Size, zoom: number): FrameRect`: zoom 0 is cover (the current crop), 1 is contain (the full frame); scale is `cover * (contain / cover) ** zoom`, centred. Zoom is clamped to [0, 1]; a zero size gives the stage rect.
- `mapLandmark(rect: FrameRect, point: { x: number; y: number }, mirrored: boolean): { x: number; y: number }`: a normalised camera landmark to stage pixels, through the same rect the wrapper uses.
- `loadZoom(storage?: Storage | null): number`, `saveZoom(zoom: number, storage?: Storage | null): void`.
- `bodyCutOff(landmarks: readonly Landmark[] | null | undefined): boolean`: true when the head (nose missing, visibility < 0.5 or y < 0.03) or the feet (both ankles below visibility 0.5, or the lower one at y > 0.97) are out of frame; false with no landmarks.
- `useCameraZoom(): number` and `setCameraZoom(zoom: number)` (useSyncExternalStore over `loadZoom` / `saveZoom`).
- Stage: on Calibrate and Play the box fills the main area (up to 1200px wide), background `--color-cam`. A `.stage__frame` wrapper holds the video and the canvas, placed by `frameRect` (ResizeObserver on the stage, the video's own size); both keep `scaleX(-1)` so `prepareCanvas` still sees the mirror. The video's `object-fit` is `fill` inside the frame, because the frame already has the video's aspect.
- `ZoomControl`: a labelled range input (0 to 1, step 0.01, testid `zoom-slider`) from "Close" to "Full frame"; at 1, while `bodyCutOff` holds (polled every 300 ms), the hint "Still too close? Step back" (testid `zoom-hint`).

- [ ] Tests at min, mid and full frame for a 4:3 camera on a 16:9 stage: the rect, `mapLandmark` of (0, 0), (0.5, 0.5) and (1, 1), mirroring; that full frame fits inside the stage with letterbox bars on one axis only; equal aspects → the same rect at every zoom; `loadZoom` with junk and blocked storage. `bodyCutOff` cases: whole body, head out, feet out, no landmarks.
- [ ] Fail, implement, pass; wire Stage and Calibrate; commit.
